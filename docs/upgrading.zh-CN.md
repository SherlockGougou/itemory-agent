## 查看当前版本

打开管理网页的「**诊断**」页，「**服务实例**」卡片中显示「**版本**」和「**实例标识**」。也可以在浏览器中打开 `http://<NAS 的 IP>:8787/api/v1/health`，查看其中的 `"version"`。

所有已发布的版本见[标签页](https://github.com/SherlockGougou/itemory-agent/tags)和[镜像包页面](https://github.com/SherlockGougou/itemory-agent/pkgs/container/itemory-agent)。

## 升级

模板使用 `:1` 标签，它始终指向最新发布的版本。升级就是下载最新镜像并重新创建容器。数据文件夹会保留，所以**不需要重新配对，也不需要重新选择文件夹**。

- **在 NAS 的应用中**（Container Manager、Container Station、Compose Manager 等）：打开项目，使用其中的“拉取”“更新”或“重新构建”操作，它会下载新镜像并重新创建容器。不同系统上的名称不完全一样。
- **在命令行中**，进入 compose 文件所在的文件夹执行：

  ```bash
  docker compose pull
  docker compose up -d
  ```

升级后请确认：

- 「诊断」页中的版本已经是新版本；
- 「**实例标识**」与升级前相同。如果变了，说明容器用的数据文件夹和之前不是同一个，App 会把它当成一台新服务器。请检查模板中 `/data` 那一行。
- 「媒体库」中的文件夹仍然显示为可读。

建议养成升级前先[备份](#备份)的习惯。

## 备份

服务的所有数据都在它的数据文件夹里（容器内的 `/data`）：

| 文件 | 内容 | 需要备份吗 |
| --- | --- | --- |
| `admin.json` | 管理员账号（密码以哈希形式保存） | 需要 |
| `tokens.json` | 已配对设备和实例标识 | 需要 |
| `settings.json` | 媒体库和全部设置 | 需要 |
| `index.sqlite`（以及 `-wal` / `-shm`） | 照片索引 | 需要；不备份的话可以通过完整扫描重建 |
| `thumbs/` | 缩略图缓存 | 不需要，缩略图会按需重新生成 |

为了得到一致的副本：

1. 停止容器。
2. 把整个数据文件夹复制到安全的地方。
3. 重新启动容器。

在容器运行时复制，可能会复制到写了一半的索引。

> [!NOTE]
> 在部分系统（包括飞牛 fnOS）上，容器写入的文件从 NAS 本身看是不可读的（权限显示为 `0000`），直接复制会失败。这时可以借助一个临时容器复制，例如：
>
> ```bash
> docker run --rm -v /vol1/1000/itemory-agent/data:/from:ro -v /vol1/1000/backup:/to alpine cp -a /from/. /to/
> ```

## 恢复或回滚

**恢复备份**：停止容器，用备份替换数据文件夹中的内容，再启动容器。实例标识和已配对设备都来自备份，所以 App 不需要重新配对就能重新连上。

**退回旧版本**：把 `image` 那一行从 `:1` 改成具体版本，例如：

```yaml
    image: ghcr.io/sherlockgougou/itemory-agent:0.4.0
```

然后重新创建容器。新版本可能已经升级过索引格式，所以请同时恢复**升级之前**做的备份。以后想重新跟随最新版本时，把标签改回 `:1` 即可。

## 卸载

1. 在 App 中，通过「**数据源设置 → 删除此数据源**」移除这个数据源。
2. 在 NAS 上停止并删除容器或项目。
3. 如果不想保留索引，删除数据文件夹（使用 `generic.yml` 时，删除对应的 Docker 命名卷）。

你的照片始终不会被改动：它们一直是以只读方式挂载的。
