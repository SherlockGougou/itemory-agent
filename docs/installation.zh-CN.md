## 开始之前

请确认：

- [ ] 你的 NAS 或电脑支持 **Docker Compose**（见[第 4 步](#第-4-步-创建容器)的列表）。部分品牌只有特定型号支持容器，不确定的话先查厂商的适用机型表。
- [ ] 你有这台 NAS 的管理员权限。
- [ ] 你知道 NAS 在家里网络中的 IP 地址，例如 `192.168.1.20`。一般可以在 NAS 的设置里，或路由器的已连接设备列表里找到。
- [ ] iPhone 上装好了 Itemory，并且和 NAS 连着同一个 Wi-Fi。

## 第 1 步 找到照片文件夹

容器默认看不到 NAS 上的文件，必须把文件夹**挂载**进去。为此你需要知道这个文件夹在 NAS 系统里的完整路径。常见位置：

| NAS | 共享文件夹通常所在位置 | 示例 |
| --- | --- | --- |
| 群晖 DSM | `/volume1/<共享文件夹>`（第二个存储空间是 `/volume2/…`） | `/volume1/photo` |
| 威联通 QTS | `/share/CACHEDEV1_DATA/<共享文件夹>` | `/share/CACHEDEV1_DATA/Multimedia` |
| TrueNAS SCALE | `/mnt/<存储池>/<数据集>` | `/mnt/tank/photos` |
| Unraid | `/mnt/user/<共享>` | `/mnt/user/Photos` |
| 飞牛 fnOS | `/vol1/1000/<文件夹>` | `/vol1/1000/Photos` |
| OpenMediaVault | `/srv/dev-disk-by-uuid-<id>/<文件夹>` | 在「存储器 → 共享文件夹」中查看 |
| Linux / 其他 | 文件实际所在的位置 | `/home/me/Pictures` |

有两种挂载方式：

- **挂载整个存储卷**（大多数模板的默认做法，例如 `/volume1`），之后在 App 里再选具体文件夹。照片分散在多个文件夹时，这种方式最省事。
- **只挂载照片文件夹**（例如 `/volume1/photo`），服务就看不到 NAS 上的其他内容。

无论哪种方式，挂载都是**只读**的：服务不可能修改或删除你的照片。

## 第 2 步 选定数据文件夹

服务需要一个可写的文件夹，用来存放自己的文件：照片索引、设置、管理员账号、已配对设备列表和缩略图缓存。按默认设置，建议预留约 6 GB 空间（缩略图缓存最多 5 GB，原图缓存最多 1 GB，另加索引）。

每个模板都已经给了一个建议位置，例如群晖是 `/volume1/docker/itemory-agent`。**启动容器之前，先用 NAS 的文件管理器把这个文件夹建好。** 请妥善保管这个文件夹：备份时备份的就是它；以后如果换了位置，App 会把服务当成一台新服务器。

> [!TIP]
> `generic.yml` 模板使用 Docker 的“命名卷”代替文件夹。命名卷由 Docker 自动创建和管理，不需要你手动建文件夹或设置权限。

## 第 3 步 选定运行用户

出于安全考虑，容器不以 `root` 身份运行，而是以模板中 `user:` 这一行指定的用户运行，格式为 `"<uid>:<gid>"`（用户 ID 和用户组 ID，都是数字）。这个用户必须能够：

- **读取**你的照片文件夹；
- **写入**第 2 步的数据文件夹。

模板默认是 `"1000:1000"`（Unraid 是 `"99:100"`，也就是 Unraid 上标准的 `nobody:users`）。它在很多系统上可以直接用，但不是所有系统都行。

最稳妥的做法是填**你自己的 NAS 账号的 ID**，这样服务能读的内容和你本人完全一样。如果你能通过 SSH 登录 NAS，执行：

```bash
id 你的NAS用户名
```

输出类似 `uid=1026(me) gid=100(users) …`，对应的就是 `user: "1026:100"`。然后把数据文件夹的属主改成这个用户：

```bash
sudo chown -R 1026:100 /volume1/docker/itemory-agent
```

不会用 SSH？先保留模板默认值继续往下做。如果有问题，管理网页会告诉你应该填哪个用户（见[第 8 步](#第-8-步-确认一切正常)），[常见问题](troubleshooting.zh-CN.md#容器启动后立刻停止)里也有具体的处理办法。

## 第 4 步 创建容器

在 [`deploy/compose/`](../deploy/compose) 中找到你的系统对应的模板，打开并复制全部内容。部署之前，修改这几处：

1. **照片路径**：第一行 `volumes:` 中第一个 `:` **之前**的部分。
2. **数据路径**：`/data` 那一行中 `:` **之前**的部分（`generic.yml` 不需要改）。
3. **`TZ`**：你所在的时区，例如 `Asia/Shanghai`。照片本身没有记录时区时，由它决定照片属于哪一天。
4. **`user`**：如果第 3 步选了其他用户，就改成那个值。
5. **`mem_limit`**：如果你的库里有超过约 1 GB 的视频，需要调大（见[内存上限](configuration.zh-CN.md#内存上限)）。

关键几行的含义：

```yaml
    user: "1000:1000"                         # 第 3 步：以哪个用户运行
    volumes:
      - /volume1:/volumes/volume1:ro          # NAS 上的路径 : 容器内的路径 : 只读
      - /volume1/docker/itemory-agent:/data   # 第 2 步的数据文件夹
    ports:
      - "8787:8787"                           # NAS 端口 : 容器端口
    environment:
      TZ: "Asia/Shanghai"                     # 你所在的时区
    mem_limit: 2g                             # 内存上限，见配置说明
```

容器**内**的路径请保持在 `/volumes/…` 下，App 会在这里查找文件夹。如果 NAS 上的 8787 端口已被占用，只改冒号**前面**的数字，例如 `"18787:8787"`。

然后创建容器。不同系统版本的菜单名称可能略有差异。

| 系统 | 模板 | 在哪里粘贴 |
| --- | --- | --- |
| 群晖 DSM 7.2+ | `synology.yml` | 在套件中心安装 **Container Manager**，然后进入「Container Manager → 项目 → 新增」。为项目选一个文件夹，选择「创建 docker-compose.yml」，粘贴后按向导完成。 |
| 威联通 QTS / QuTS hero | `qnap.yml` | 「Container Station → 应用程序 → 创建」，粘贴后点「创建」。 |
| TrueNAS SCALE 24.10+ | `truenas.yml` | 「Apps → Discover Apps → Custom App」，选择通过 YAML 安装，粘贴。仅支持 `amd64`。 |
| Unraid | `unraid.yml` | 先从 Community Applications 安装 **Compose Manager** 插件，然后「Docker → Compose → Add New Stack」，编辑该 stack 并粘贴，再点「Compose Up」。仅支持 `amd64`。 |
| 飞牛 fnOS | `fnos.yml` | 打开 **Docker** 应用 →「Compose」→ 新建项目并粘贴。 |
| OpenMediaVault | `omv.yml` | 安装 **openmediavault-compose** 插件（来自 omv-extras），然后「服务 → Compose → Files → 添加」，粘贴、保存，再点「Up」。 |
| 装有 Docker 的 Linux | `generic.yml` | 保存为一个空文件夹里的 `compose.yaml`，在该文件夹执行 `docker compose up -d`。 |

第一次启动会从 `ghcr.io` 下载镜像（约 240 MB），不需要任何账号或登录。

## 第 5 步 创建管理员账号

在同一网络中的电脑上打开：

```text
http://<NAS 的 IP>:8787
```

请使用 NAS 真实的局域网地址，不要用 `localhost`：你在这里打开的地址会被写进配对二维码。

第一次访问会要求**设置管理员账号**。用户名 3–64 个字符，密码**至少 12 位**。密码只以哈希形式保存，无法找回；忘记了请看[忘记管理员密码](troubleshooting.zh-CN.md#忘记管理员密码)。

## 第 6 步 配对 iPhone

1. 在管理网页打开「**配对与设备**」，点「**开始配对**」，页面会显示二维码。二维码 5 分钟内有效，只能使用一次。
2. 在 iPhone 上打开 Itemory，进入「**数据源 → Itemory 私有云服务 → 扫描二维码**」。
3. 用相机对准二维码，App 会提示配对完成。

要配对另一台 iPhone，再点一次「开始配对」生成新的二维码即可。

## 第 7 步 选择要索引的文件夹

刚配对的服务还没有任何媒体库。在 App 中：

1. 打开「**Itemory 私有云设置 → 媒体库 → 添加文件夹**」。
2. 选择存放照片和视频的文件夹。它们显示在 `/volumes/…` 下，也就是你在第 4 步设置的路径。
3. 保存后，服务立即开始建立索引。

第一次扫描可能需要几分钟到几个小时，取决于文件数量和 NAS 的性能。扫描进度会显示在 App 的「Itemory 私有云设置」和管理网页的「**概览**」页中。之后服务每天夜里 03:00 检查一次变化，只读取新增或修改过的文件。

## 第 8 步 确认一切正常

在管理网页中查看：

- 「**概览**」显示扫描进度和一组健康检查项。
- 「**媒体库**」把每个挂载进来的文件夹标为「可读」或「不可读」。如果有文件夹不可读，「挂载点」下的「**建议运行用户**」会告诉你 `user:` 应该填哪个值。把它填进模板，确认数据文件夹也属于这个用户，然后重新创建容器。
- 「**诊断 → 外部工具**」中，`vipsthumbnail`（图片）和 `ffmpeg`（视频与实况照片）都应显示为可用。
