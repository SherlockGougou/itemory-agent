## 模板参数

| 参数 | 默认值 | 作用 | 需要改吗 |
| --- | --- | --- | --- |
| `image` | `ghcr.io/sherlockgougou/itemory-agent:1` | 要运行的镜像。`:1` 始终指向最新发布版本；想固定版本可以写成 `:0.4.0` 这样的具体版本号。 | 只在需要固定版本时 |
| `user` | `"1000:1000"` | 服务以哪个用户 ID 和用户组 ID 运行，见[安装指南第 3 步](installation.zh-CN.md#第-3-步-选定运行用户)。 | 文件夹不可读时 |
| `volumes` | 视模板而定 | 照片文件夹（只读，挂在 `/volumes/…` 下）和数据文件夹（`/data`）。去掉 `:ro` 之前先读[删除照片](#删除照片)。 | 必须改 |
| `ports` | `"8787:8787"` | `NAS 端口:容器端口`。 | 8787 被占用时改第一个数字 |
| `TZ` | `Asia/Shanghai` | 时区，用于判断照片属于哪一天。 | 按实际时区修改 |
| `ITEMORY_PRESET` | `balanced` | 初始的[性能档位](#性能档位)，只在第一次启动时生效。 | 可选 |
| `mem_limit` | `2g` | 内存上限，见[内存上限](#内存上限)。 | 有大视频时 |
| `cpus` | `"1.5"` | 最多使用的 CPU 核数，见[CPU 上限](#cpu-上限)。 | 可选；单核机器必须调低 |
| `restart` | `unless-stopped` | 崩溃或 NAS 重启后自动重新启动。 | 不需要 |
| `read_only`、`tmpfs`、`cap_drop`、`security_opt` | 已启用 | 安全加固，见下表。 | 不需要 |

安全加固参数可以放心保留，服务就是按这些限制设计的：

| 参数 | 作用 |
| --- | --- |
| `read_only: true` | 容器自身的文件系统只读，服务只向 `/data` 写入。 |
| `tmpfs: /tmp` | 图片解码用的临时空间。HEIC 或 RAW 文件较多时可调到 `256m`。 |
| `cap_drop: [ALL]` | 去掉全部 Linux 特殊权限。 |
| `no-new-privileges` | 容器内的进程不能提升权限。 |
| 照片文件夹的 `:ro` | 服务不能写入、移动或删除你的照片。这是默认状态，也是主要的保护手段，见[删除照片](#删除照片)。 |

另外还有两个供高级用法使用的环境变量，镜像里已经设置好，除非明确知道为什么要改，否则不要动：`ITEMORY_CACHE_DIR`（数据文件夹，`/data`）和 `ITEMORY_HTTP_ADDR`（监听地址，`:8787`）。

## 性能档位

一个档位会同时设定多项资源上限。首次启动时用 `ITEMORY_PRESET` 选择，之后在 App 的「**Itemory 私有云设置 → 资源预设**」中修改。

| 档位 | 并行任务数 | 缩略图尺寸 | 缩略图缓存 | 夜间生成上限 |
| --- | --- | --- | --- | --- |
| `light` | 1 | 256 px | 1 GB | 2,000 |
| `balanced`（默认） | 2 | 512 px | 5 GB | 5,000 |
| `performance` | 4 | 512 px | 10 GB | 20,000 |

内存较小的 ARM NAS 建议用 `light`；CPU 和磁盘空间充足的机器可以用 `performance`。选定档位之后，仍然可以在 App 里单独修改其中任何一项。

## 后台生成缩略图

缩略图是照片的一份小尺寸 JPEG，或者视频的一帧画面，保存在数据文件夹的 `thumbs/` 下。App 滚动浏览时显示的是缩略图，打开某张照片时才加载原图。

服务通过两种方式生成缩略图：

- **提前生成。** 每次扫描结束后（夜间扫描、添加文件夹后的第一次扫描，或者你手动发起的扫描），服务按从新到旧的顺序检查整个媒体库，把还没有的缩略图补上。
- **请求时生成。** App 请求的缩略图还不存在时，服务当场生成。这张照片第一次显示会稍慢，之后就是立即显示。

App 里有三项设置限制提前生成的工作量：

| App 中的设置 | 作用 |
| --- | --- |
| 「**夜间生成上限**」 | 一次扫描之后最多生成多少张缩略图。大型媒体库因此会分几个晚上生成完，NAS 不会一直忙到早上。设为 `0` 表示不提前生成，缩略图只在请求时生成。 |
| 「**同时处理的任务数**」 | 同时处理多少个文件。 |
| 「**私有云缓存上限**」 | 缩略图缓存的大小。缓存用到 90% 时停止提前生成；缓存用满时，最久没有用到的缩略图最先被删除。 |

粗略估算：一张 512 px 的缩略图占 40–80 KB，5 GB 的缓存能放下 8 万张左右。媒体库比这更大时，可以调高缓存上限，或者让最早的照片在请求时再生成缩略图。

App 里的「**清空缓存**」会删除全部缩略图，并停止正在进行的提前生成。其他数据不受影响，缩略图会在请求时和下一次扫描后重新生成。

## 内存上限

内存是唯一需要对照你自己的媒体库检查的上限。设得太低时，缩略图或视频封面任务会被系统终止，而且是**静默失败**：你唯一能看到的现象是部分缩略图一直不出现。

**决定内存需求的是库里最大的单个视频，而不是文件数量。** 在一台 24 核 x86 NAS 上实测：对一个 2 GB 视频抽帧，512 MB 时失败，768 MB 及以上成功。减少并行任务数没有帮助，因为一个大视频始终由单个进程处理。

按库里最大的单个文件选择 `mem_limit`：

| 最大的单个文件 | 建议 `mem_limit` |
| --- | --- |
| 100 MB 以内（纯照片） | `512m` |
| 500 MB 以内 | `1g` |
| 1–2 GB | `2g`（模板默认值） |
| 超过 2 GB | `4g` 或更高 |

任务被终止时不会留下明确的错误信息，所以最好一开始就按最大的文件来定上限。如果有缩略图一直缺失，调高上限后再看。不要以容器报告的内存峰值为准：Linux 会把文件缓存也算进容器内存，这个数字不能反映服务真正需要多少内存。

## CPU 上限

`cpus` 只影响速度，不影响结果。它不能超过机器的 CPU 核数：在单核 NAS 上，必须先把它改成 `"1"` 或更小，Docker 才能创建容器。模板取 1.5 核，避免第一次整库扫描时拖慢小型 NAS 上的其他服务。在一台性能较强的机器上，同一批缩略图在 1.5 核限制下的耗时约为不限制时的 16 倍。如果第一次扫描太慢，可以临时调高 `cpus`，建完索引后再调回。

## 删除照片

删除**默认关闭**。除非你主动开启，服务不会移除任何文件；而且必须同时满足两个互相独立的条件：

1. **照片文件夹要挂载为可写。** 所有模板都用 `:ro`（只读）挂载照片文件夹。把这一行末尾的 `:ro` 去掉，例如把 `/volume1:/volumes/volume1:ro` 改成 `/volume1:/volumes/volume1`，然后重新创建容器。
2. **`deleteMode` 必须是 `trash` 或 `permanent`。** 它在服务的设置里（`/data/settings.json` 的 `deleteMode` 键），默认是 `off`。用设置接口修改，例如：

```bash
curl -X PATCH http://<你的NAS地址>:8787/api/v1/settings \
  -H "Authorization: Bearer <设备令牌>" \
  -H "Content-Type: application/json" \
  -d '{"deleteMode":"trash"}'
```

两者缺一，删除都会被拒绝：文件夹仍是只读，或者请求返回 `403 delete_disabled`。只有当运行中的服务上报了 `delete` 能力位时，App 才会显示删除入口，而它只在 `deleteMode` 不是 `off` 时才会上报。删除对单个文件是全有或全无的：要么文件被移动或删除，要么什么都不变，并返回一个带具体路径的错误。

| `deleteMode` | 删除时会发生什么 |
| --- | --- |
| `off`（默认） | 删除被拒绝，返回 `403 delete_disabled`。服务只读取。 |
| `trash` | 文件被移动到 `<媒体库根>/.itemory-trash/` 下，保留原有子目录结构，文件名加上时间戳前缀，不会覆盖回收站里更早的同名文件。 |
| `permanent` | 从磁盘上直接删除文件，无法撤销。 |

用 `trash` 时，原路径会立刻从媒体库里消失，文件留在媒体库根目录下：

```text
/volume1/photos/2024/IMG_0001.jpg   →   /volume1/photos/.itemory-trash/2024/20260117T101500.123456789_IMG_0001.jpg
```

`.itemory-trash` 以点开头，扫描会跳过它，被移动的文件不会再次出现在 App 里。要还原文件，把它从 `.itemory-trash` 移回原来的位置，然后跑一次扫描；要回收空间，由你自己删除 `.itemory-trash` 文件夹。

删除被拒绝时返回这些错误：

| 响应 | 含义 |
| --- | --- |
| `403 delete_disabled` | `deleteMode` 是 `off`。 |
| `403 read_only_mount` | 需要写入的目录不可写——文件所在目录或回收站目录，通常是照片文件夹以只读方式挂载（`:ro`）。去掉 `:ro` 并重新创建容器。 |
| `500 delete_failed` | 其它写入失败，例如文件被占用，或文件系统拒绝该操作。错误信息里会给出具体路径，文件保持原样。 |
| `403 outside_library` | 索引里的路径已经不属于任何已配置的媒体库。 |
| `404 not_found` | 没有这个 id 的有效条目。 |

> [!IMPORTANT]
> 删除是服务唯一会在你的照片文件夹里写入的操作，而且只有在两个开关都打开时才生效。把 `deleteMode` 改回 `off`、把 `:ro` 恢复回去，服务就回到只读行为；但已经删掉的文件不会因此回来。

## App 中的设置

以下设置在 Itemory App 的「**Itemory 私有云设置**」中修改，保存后立即生效：

| 设置 | 作用 |
| --- | --- |
| 「**媒体库**」 | 索引哪些文件夹。保存后立即开始一次扫描：新加的文件夹被索引，移除的文件夹从 App 中消失。 |
| 「**不扫描的文件夹**」 | 永远不被索引的文件夹名和文件名。`@eaDir`、`#recycle`、`#snapshot`、`.Trash`、`$RECYCLE.BIN` 等系统文件夹默认已跳过。 |
| 「**资源预设**」 | 一次切换某个[性能档位](#性能档位)的全部数值。 |
| 「**缩略图清晰度**」 | 缩略图的像素尺寸。尺寸越大，在大屏幕上越清晰，占用的缓存也越多。旧尺寸的缩略图留在缓存里，直到被淘汰。 |
| 「**私有云缓存上限**」 | 缩略图缓存的最大容量。调低后立即释放空间。 |
| 「**夜间自动扫描**」「**扫描时间**」 | 是否每天自动扫描，以及在几点扫描（默认 03:00，按容器时区）。 |
| 「**同时处理的任务数**」 | 扫描和生成缩略图时并行处理多少个文件（1–8）。 |
| 「**夜间生成上限**」 | 见[后台生成缩略图](#后台生成缩略图)。 |
| 「**扫描新增内容**」 | 立即查找新增、修改和删除的文件。没有变化的文件不会被重新读取。 |
| 「**重新扫描全部**」 | 重新读取每一个文件。只在修改了 `TZ`，或[常见问题](troubleshooting.zh-CN.md)要求时才需要。 |
| 「**实况照片识别**」 | 把同一文件夹里同名的照片和视频配成一对，按实况照片播放。 |
| 「**日志详细程度**」「**服务端日志**」 | 服务记录多少日志，以及最近的日志内容。 |

「**视频转码**」是为后续版本预留的选项，目前不起作用：服务按视频的原始存储格式发送给 App。

管理网页用于查看状态、日志和诊断信息，管理配对和已配对设备，也可以修改档位、缩略图尺寸、缓存上限和扫描时间。媒体库和不扫描的文件夹只能在 App 中修改。

`deleteMode` 还不在这个列表里：本版本的控制台和 App 都没有它的开关。请用[删除照片](#删除照片)一节的 `PATCH` 请求设置；不确定时保持 `off`。

## HTTPS 与远程访问

服务在 8787 端口上使用普通 HTTP。在可信的家庭网络里没有问题，但请注意：

- **通过 HTTP 登录时，管理员密码以明文传输。** 如果你不信任网络中的其他人或设备，请用 NAS 自带的反向代理为管理网页加上 HTTPS。服务能识别标准的 `X-Forwarded-Proto`、`X-Forwarded-Host` 和 `X-Forwarded-Port` 请求头，所以通过代理生成的二维码里会是代理的 HTTPS 地址；此时 iPhone 需要信任该证书。
- **不要在路由器上把 8787 端口转发到公网。** 服务是为家庭网络内部使用设计的。
- 在外面使用时，请让 iPhone 通过你自己控制的 VPN 连回家里的网络，App 就能像在家一样访问 NAS。
